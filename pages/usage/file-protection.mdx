# File Protection

File protection encrypts files when they are downloaded from the session file browser. This prevents accidentally executing malicious files and ensures downloads are handled intentionally.

## How It Works

When a user clicks a file in the session's file browser (`/files/`), the request is handled by an on-demand zip server running inside the container. Instead of serving the raw file, nginx routes the request to this server which packages the file into a password-protected **7-Zip AES-256 encrypted** archive on the fly and streams it directly to the browser.

When `FILE_PROTECTION=false`, the same zip server still handles file requests but delivers the raw file as a direct download attachment — no encryption, no archive.

| Mode | Behaviour |
|---|---|
| `FILE_PROTECTION=true` | Files delivered as password-protected `.7z` archives (`filename-PROTECTED.7z`) |
| `FILE_PROTECTION=false` | Files delivered as direct downloads with correct MIME type |

The original files inside the container are never modified or deleted in either mode.

## Enabling File Protection

Like network logging, file protection can be enabled at three levels:

1. **Global (SiteSettings)** — admin enables/disables it platform-wide
2. **Workspace** — workspace owners/admins can override the global setting
3. **Per session** — if allowed by the workspace, users can toggle it at launch time

## Decrypting a Protected File

You will need 7-Zip or a compatible tool. The password for all protected archives is **`infected`**.

**Linux/macOS:**

```bash
7z x filename-PROTECTED.7z -pinfected
```

**Windows:**

Right-click the `.7z` file → **7-Zip** → **Extract here**, then enter `infected` when prompted.

## Why Use File Protection?

Encrypted delivery ensures:

- You cannot accidentally double-click and execute a malware sample
- Files from high-risk sites are contained until you consciously choose to decrypt them
- There is a clear audit trail (the encrypted file) of what was retrieved during the session
