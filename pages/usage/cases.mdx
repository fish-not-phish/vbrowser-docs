Cases let you organize browser sessions into structured investigations. Each case can contain linked sessions, notes, tags, comments, and files (uploaded attachments or links to workspace storage).

## Creating a Case

1. Navigate to **Cases** in your workspace sidebar
2. Click **New case**
3. Enter a name and optional description
4. Choose a status: `open`, `closed`, or `archived`

## Case Status

| Status | Meaning |
|---|---|
| `open` | Active investigation |
| `closed` | Investigation complete |
| `archived` | Preserved for record-keeping; no longer active |

## Linking Sessions to a Case

Sessions can be linked to a case from the session detail view in [Session History](/usage/session-history). A single session can belong to one case.

## Tags

Tags are colored labels you can apply to sessions to categorize them (e.g. by threat actor, campaign, or topic). Tags are scoped to the workspace.

To create a tag:

1. Go to **Cases** → **Tags**
2. Click **New tag**, enter a name, and pick a color

To apply a tag to a session, open the session in history and select tags from the detail panel.

## Session Notes

Each session can have a rich-text note attached to it. Notes are written with the BlockNote editor, which supports:

- Headings and paragraphs
- Bullet and numbered lists
- Bold, italic, and other inline formatting
- Code blocks

Notes are stored per-session and are accessible from the session detail view.

## Case Comments

Cases have a comment thread for team collaboration. Any workspace member can add comments.

## Files on a Case

A case can reference files in two ways:

| Source | Description |
|---|---|
| **Upload** | A file attached directly to the case. Limited to 50 MB per file and stored on the server's local filesystem, or in S3 if `AWS_STORAGE_BUCKET_NAME` is configured. |
| **Workspace file** | A read-only link to a file that already lives in the workspace's [persistent storage](/usage/persistent-storage). No bytes are copied — the case only stores a pointer to the S3 path. |

The **Files** tab on a case lists both kinds together, sorted newest-first.

### Linking a Workspace File

1. Open the case and go to the **Files** tab
2. Click **Link file** and pick a file from the workspace's persistent storage
3. The file appears on the case immediately

Linking a file requires the `analyst` role or higher. Removing a link from a case does **not** delete the underlying S3 object — it only removes the reference. If the source object is later deleted from storage, the link remains on the case but is marked as missing.

### Downloading Files

Every file downloaded from a case is wrapped in a password-protected **7z** archive (`<filename>-PROTECTED.7z`, password `infected`). This applies to both uploads and workspace file links. See [File Protection](/usage/file-protection) for extraction instructions.

## Case Detail View

The case detail page shows:

- Case metadata (name, description, status, created date)
- All linked sessions with summary info
- Comment thread
- Files (uploaded attachments and linked workspace files)

From here you can also change the case status or edit the description.
